# 这份仓库是怎么长出来的

> 给三个月后回来改代码的人，也给第一次读这个仓库的人。
> 这里的「确定性」不是文风，是一条条被实测否掉的路换来的。

## 一、三条写法约定

| 约定 | 反例 | 为什么 |
|---|---|---|
| 每个数字都带样本量和条件 | 「首 token 119ms」 | 同一个 1.5B 模型量到 119ms 和 247ms 都是真的，差别只是第一句多长。没写清条件的「首句 xxx ms」不能横比 |
| 缺失写 `-1`，不写 `0` | `eou_latency_ms: 0` | 0 会被平均进去，等于伪造了一次「零延迟」 |
| 被否掉的方案留档 | 悄悄删掉 `pipelined` | 不留档，下一个人会把它再试一遍 |

第三条最反直觉：**否定结论比肯定结论更值钱**，因为它省的是别人的时间。

## 二、四次自我推翻

| 方案 | 当初的预期 | 实测 | 现在的定性 |
|---|---|---|---|
| M4 投机流水线（说话中就拿 ASR partial 预推理） | 把合成藏进尾段，够到 300ms | 命中率 **1/24 = 4%**，p50 **2491ms** vs 串行 1840ms，常态慢 **651ms** | 净负债。命中率低是原理性的（用户改口、ASR 回改），不是参数没调对 |
| 每路独占推理资源 | 独占 = 不互相拖慢 = 更快 | 首轮双路每路 p50 **2163ms**，共享 1653ms，**净亏 510ms**；把 ONNX decode 搬进线程后复测 1628 vs 1589（回到噪声内），并行度 1.78x | 并发是稳定性指标，不是速度指标。别报成加速 |
| 把 TTS 首片拆得更细 | 首片越小，首音越早 | p50 **404ms**，当前 provider 无可行收益 | 记下天花板，不再投入 |
| 默认判停档用 `neural` | 判停 100ms，账面上最优 | 真人半句停顿，抢话 **3/3** | 退回 `conservative`（515ms）。「快」和「不抢话」是同一个旋钮的两头 |

四次里有三次，是**自己的方案被自己的数据干掉**。这不是谦虚，是记账方式决定的：
先写预期，再跑，跑完只准改结论，不准改口径。

## 三、一个反直觉的发现：延迟大头不在合成

从 10 轮真机录屏里逐帧读出来（每一轮行尾挂着毫秒数，点开能看拆解）：

- 模型想出第一个字（首 token）：**112~169ms**
- 合成第一片声音：**30~59ms**
- 打断那一轮更极端：首 token 301ms、TTS 88ms、判停 900ms

所有人在卷 TTS 首包，它其实是四块里最小的一块。波动最大的那块是「模型想出第一个字」。

由此多一条选型判据：**语音链路不能比首 token，要比 `首 token + 首句字数 ÷ 出字速度`**——
合成要攒到句末标点才开工，首 token 早到 200ms，只要第一句没写完，合成端一动不动。

这条判据现场就能证伪掉一批候选：名字带 `flash` 不等于不思考（`qwen3.8-flash` 先吐 92 字思考链，
第一个可播句子 2771ms），所以「能不能关掉思考」是选型前置条件，不是调优项。

## 四、一次真实交付：153 秒录屏 → 90 秒

这是仓库之外的一次工作，但方法跟这个仓库是同一套。

- 原片 153 秒。抽帧拼联系表，18 格长得几乎一样，**看不出问题**
- 转成文字才看出来：25.8–81.1 秒那 55 秒是个陷入复读的笑话（同一句式重复到第十一个），占全片 36%
- 删掉之后 90 秒。切点全部吸附到 `silencedetect` 检出的静音区间内，避免切半句
- 验收也看转写、不看画面：新成片 18 句完整连贯

教训：**联系表只能看构图，看不出内容坏了。** 判断内容坏没坏，必须落到文字或音频上。

顺带一条拼接的坑：不能用 `-c copy` 直接拼。AAC 有 priming，会让音频提前约 1.9 秒——
不报错、能播、音画错位。必须从源一次性重编。

## 五、开源前的那次体检

工作区干净 ≠ 历史干净。

| 检查 | 结果 |
|---|---|
| key / token / 手机号 / 邮箱 | 无 |
| `models/` `data/` `.venv/` `.env` | 均未跟踪；跟踪 192 个文件，最大 628K |
| 唯一的环境指纹 | `deploy/` 里的 ECS 公网 IP（当前文件 2 处 + 一个默认值） |

改完当前文件不够——**那个 IP 还躺在 131 个历史 commit 里**。用 `git filter-branch` 重写全部历史，
再删备份 ref、过 reflog、`gc --prune=now`，`.git` 从 9.8M 降到 1.2M。

两个坑：

1. `git log --all -S"IP"` 会命中 `refs/original/`，看起来像没清干净。**先删备份 ref 再查**，否则会自己骗自己。
2. 第一次漏了 `--tag-name-filter cat`，6 个 tag 还指着旧 commit。tag 也是引用，会把旧历史一起带到远端。

最后用 `git clone --mirror` 拿远端快照逐 commit 扫，才算验完。**本地验不算，要看远端。**

## 六、为什么「差距表」是交付物

它不是免责声明。生产级 = 修到位的功能 + 如实声明的差距，两者都是交付物。

一个具体例子：`missed_eou` 曾经是个「恒为 0」的指标——`run_turn` 采完指标就 `reset()`，
把「判停后又出现人声」的证据擦掉了。观察窗跨 `reset` 存活之后它才有数。

**一个报 0 的指标，可能是没埋点，不是没发生。** 差距表里那些「这项不可用」的行，
大部分是这么查出来的。

## 七、这些记录存在哪里

上面这些「当时为什么这么定」，不是靠记忆写的。

每一次改档、每一个被否掉的方案、每一次验收的原始账单，都先落进自建的知识库
（[ExoMind](https://exomind.ai-as.cn)），写文章和复盘时靠检索捞出来。工具与本链路无关，
只是这套记录法子需要它——**推翻过的结论如果不留档，第二次一定会重犯。**
