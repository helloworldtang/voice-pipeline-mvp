一轮语音的时间轴：每个 span 的角色、依赖与并行边界

取该轮真实账单（口径B 856ms，共 9 格）。横条长度就是该 span 的自有时间，位置按发生顺序。 实线墨框＝首音的关键路径（串行，一环不完成下一环不启动）；虚线灰＝等待； 珊瑚虚线＝可并行但当前没做的那一格。判停段为压缩显示。

角色与产出

谁在干什么，交给谁

上行麦 / uplink.frame
每 100ms 一帧麦克风音频，贯穿整轮（含 AI 说话期间）——打断能工作的前提。
判停 EOU / eou.update
每帧都喂（能量门只拦 ASR，不拦它）。判「说完了吗」，产出一次 EOU 判定。
ASR / asr.finalize
把这一轮的音频收成终稿（24ms），随即 reset 开新流，防止下一轮音频进死流。
LLM / headers → first_sentence
终稿 → 首 token（TTFT 314ms）→ 首句完整（123ms）。首句一完成就交给 TTS。
TTS / connect → first_byte
借一条热连接（43ms）→ 服务端合成首片（302ms）→ 切成 200ms 分片。
播放 / 下行
客户端把分片背靠背排程出声；停播时丢弃未出声的排程（本轮 1830/287ms 的证据）。

协作规则

五条硬规则

  • 一环不完成，下一环不启动：EOU → finalize → LLM 首 token → 首句 → TTS 首片。首音只能等这条链。
  • 一句一合成：LLM 吐到句末标点就送 TTS；合成期间 LLM 流被背压，所以 llm.request 的时长≈TTS 时长——不是模型慢。
  • 上行不停：AI 说话时麦仍在上行，EOU 仍每帧判——否则打断永远触发不了。
  • 轮外预热：连接池/预热在口径B 之外完成，所以 connect 只剩 43ms。
  • 出队即下发：outbox → pump 串行；tx.first_audio ≈0，音频不排队。

并行边界

三类，别混

已并行（3 处）
上行帧 ↔ 下行合成；播放 ↔ 剩余合成；池预热 ↔ 整轮。
可并行但未做（1 处）
LLM 下一句 ↔ TTS 当前句。机制上确实串行（句 2 合成起点 = 句 1 终点）；首音确定不变，墙钟会短；但 感知收益 ≈ 0（本轮 2 句：句 2 首片比句 1 播完早 86ms），单句回答更是零。
不可并行（关键路径）
判停 → finalize → LLM 首 token → 首句 → TTS 首片。要压首音，只能压这五段之一。
