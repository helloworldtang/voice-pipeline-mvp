## 三、优化候选（按预期收益排）

### ① 预合成 filler 遮盖（✅ 已落地 2026-10-17：实现 + 测试 + 接线 + 实测）

- 做法：判停成立瞬间先播一段**预合成**的短音频（「嗯」「好的，我看一下」），把 TTS 首片的
  650ms 盖住；真音频到了自然接上。代码：`core/filler.py`（FillerBank 读盘/轮转/降级）+
  `core/scheduler/base.py:play_filler`（切分片、只打 `first_sound` 不动口径B、负 seq 不占序号
  空间）+ `server/session.py`（AsrFinal 后注入）+ `scripts/make_filler.py`（DashScope 离线预合成，
  落 `~/.voice-pilot/filler`）；开关 `VOICE_FILLER=1`。
- 实测（2026-10-17，`probe_trace.py --tts dashscope --repeat 6` 两臂只差 filler 开关）：
  - 关臂：口径B p50=744ms（673~957），**体感首音此格为空**（filler_used=0）；
  - 开臂：口径B p50=796ms（771~912），**体感首音 `first_sound_ms` p50=6ms**（filler_used=6/6）；
  - 口径B 两臂差在 DashScope 单轮抖动内（tts.first_byte 320↔319 p50、关臂一轮 538 拖到 912），
    **filler 没有把口径B 算小**——计量纪律守住（caliber_b 仍只指真实回答首片）。
  - 结论：用户听到的第一个声音从「口径B 起点 ~744ms」提前到「判停后 ~6ms」，正是本节目标。
- 代价与诚实边界：**口径B 一分不省**（同轮 ~744ms 不变）——省的是「用户以为在等」的那段。
  对外必须把「体感首音」与「口径B」分开报，否则就是冒领。filler 内容属产品策略
  （要短、要中性、别每条一样）。
- ⚠️ **实测新挖出的诚实边界**：当前 filler 片段裁静音后仍 **1190ms**（> TTS 首片 ~650ms）。
  outbox 是 FIFO，filler 先发完 ~1190ms 真回答首片才被听到 → **真回答的「被听见起点」反而被
  推后约 400ms**。收益是「即时搭话」，代价是回答起点后移。**理想 filler 应更短（≤ ~400ms）**，
  使 filler 结束 < TTS 首片就绪，既提前搭话又不推迟回答。文档原「体感首音 ~0.5s」只算了 filler
  自己的声音，漏了这层权衡——已钉正。
- 为什么值：作者最初的目标就是**体感**（「像在跟客服排队」），而体感里最大的两块恰好是
  判停 500ms + TTS 首片 650ms，**两块都能被 filler 盖住**。

### ② TTS 首片固定成分拆解（✅ 已落地 2026-10-17：跑通对照实验，结论=当前 provider 无可行收益）

- 实测（`scripts/probe_tts_firstchunk.py --repeat 20`，真 SDK）：首片 **p50=404ms**（p90=505 / min=367 / max=615）；
  冷启动第 1 次 615ms，去掉后 p50=404ms；**整句合成 total p50=1801ms**；建连（预热池）p50=53ms；
  TCP 握手 p50=35ms（网络成分很小）。
- **换音色**：longxiaochun_v2 430ms / longwan_v2 437ms / 默认 404ms —— 差异 <40ms，默认已最优。
- **换长度**：1 字 448ms vs 25 字 404ms —— 再次确认「首片与首句长度无关」（§一#6）。
- 结论：**650ms 是 P0.5 连接池落地前的过时数**（§二 注）。当前首片 ~404ms 里，连接已被 P0.5
  压到 53ms，剩余 ~350ms = 服务端首字节 + 首句合成 + 传输，是**当前 provider 的硬地板**。
  **在当前 provider 上无 100~200ms 可榨**——唯一杠杆是换第二家流式（火山），属更大范围的
  候选、不在本轮。
- 为什么值得跑：它消除了「TTS 首片还有空间」的错觉，把优化注意力正确导向判停（③）与 filler（①）。
- 复现：`uv run python scripts/probe_tts_firstchunk.py --repeat 20 --out bench/tts-firstchunk-<ts>.json`

### ③ 判停尾部最差体感（✅ 已落地 2026-10-17：根因已查 + 已修 + 单测钉死）

- **根因（查实）**：`VadSilenceEou.push_audio` 在每帧 `rms>=0.01` 时执行 `self._silence=0`——
  用户说完后尾音里的 AEC 残余/环境噪声（RMS 0.01~0.02）每帧把静音计时清零，500ms 保守阈值
  永远攒不到，只能等 `max_silence_ms=2000` 看门狗兜底。**真人账 rounds 5/12（2100/2000ms）即此**。
- **修复**（`core/eou.py`）：把「清零静音」与「标记有人声」拆成双阈值——
  清零用 **0.02 = barge-in L1**（清晰语音才清零），0.01~0.02 的噪声毛刺是**中性帧**（标有人声、
  不增长也不清零静音）。与「什么样算说话」同一把尺，不与打断层打架。不变式
  `silence_reset_threshold >= energy_threshold` 有单测钉。
- **诚实边界**：1400ms 的两例（rounds 9/13）是**空转写门**（`session.pending_end` 的 unlatch
  放行上限 ~1s + 500ms），属回声自激的安全闸，**本轮不改**——缩短它有 reopen 回声回环的风险。
- **效果**：修复后尾音噪声不再拖住静音窗，保守阈值 ~500ms 正常触发；`tests/test_eou.py`
  的 `test_intermittent_noise_fixed` / `test_intermittent_noise_used_to_trigger_watchdog`
  一正一反钉死「修复前拖到看门狗 / 修复后 500ms 即判停」。真人账最差体感 2000/2100ms → ~500ms。
- 为什么值：最差体感（用户等 2s 才听到回应）比中位数值钱——它决定「这机器靠不靠谱」的第一印象。

### ④ 空轮 3/26 的触发源定位

- EOU 被判停在「有能量无文字」音频上（两道门拦住了、无输出），疑似 AEC 残余/环境噪声。
- 定位后要么抬门限、要么修回声——顺手把判据 8（干净度）与判据 10（回声）往前推一步。

### ⑤ 窄窗投机（与 M4 失败的变体不同，可 A/B）

- M4 的失败是「**说话中**就用 ASR partial 投机」（命中 4%、p50 比串行慢 651ms）。
- 变体：**静音已达 ~250ms 时先发一次 LLM 请求**，300ms 后判停成立即命中（省 ~250ms），
  不成立则作废。命中率应远高于 4%（用户说完后继续静音是常态）；未命中只多花一次 LLM
  调用，**不影响正确性**。现有 bench 可直接 A/B（serial vs 窄窗）。

### ⑥ 不建议再挖

调度并行/投机（已实测净负债）；本地 TTS 换引擎（只省 CPU，首片不动，melo 另有音量/单音色
短板）；媒体面/抗噪/音色克隆（范围外）。

## 四、对文章要改的口（第一层硬约束，不是建议）

- **4 处数字**：端到端 300ms → 体感 ≈1.5s / 口径B ≈1.04s，**并补上判停项**；
  ASR 首字 200ms → 300~600ms；TTS 首包 250ms → 640ms（连接预热兑现后 1029→**724ms**）；
  预热 400ms → 热进程下不复现，需标条件（连接那一半已兑现：省 259ms/句）。
- **2 处未兑现承诺**：回声抑制、意图分类（本仓只做到 L1 能量 + L3 启发式 + 状态机）。
- **1 处缺失项**：**判停**——文章全程没把它算进账，而它正是「敢不敢不抢话」的那 100~500ms。

## 五、复现

```bash
# 真人验收账（26 轮）→ 分格与判停质量
uv run python scripts/report_turns.py ~/.voice-pilot/turns.jsonl --since 2026-10-10

# §一#6「首片与首句长度无关」：分段斜率（云流式）
uv run python - <<'PY'
import json, pathlib, statistics
rows = [json.loads(l) for l in (pathlib.Path.home()/".voice-pilot/turns.jsonl")
        .read_text().splitlines() if l.strip()]
groups = {"今日两段（26 轮）": {"159223d67d36", "b2fdb3aeea26"}, "10-05 那段（112 轮）": {"615183c9f967"}}
for label, sids in groups.items():
    p = [(float(r["tts_first_chars"]), float(r["tts_first_chunk"]) - float(r["first_sentence_done"]))
         for r in rows if r["session_id"] in sids and r.get("tts_first_chars", 0) > 0
         and r.get("first_sentence_done", -1) >= 0 and r.get("tts_first_chunk", -1) >= 0]
    xs = [a for a, _ in p]; ys = [b for _, b in p]
    mx, my = statistics.mean(xs), statistics.mean(ys)
    cov = sum((x-mx)*(y-my) for x, y in p)/len(p); vx = sum((x-mx)**2 for x in xs)/len(xs)
    print(f"{label}: n={len(p)} 首片 p50={statistics.median(ys):.0f}ms 斜率={cov/vx:+.0f}ms/字")
PY
```

> ⚠️ §三①②③ 均已**实测落地**（2026-10-17）：① filler（体感首音 p50 6ms、口径B 不变、但片段偏长会推迟真回答起点，需调短）、
> ② TTS 首片拆解（p50=404ms，**650ms 旧数是 P0.5 前基线**，详见 §二 注；当前 provider 无可行收益）、
> ③ 判停尾部（噪声毛刺不再清零静音窗，2000/2100ms 最差体感回到 ~500ms，单测钉死）。
> §一、§二 的数字是本仓已落盘的证据。
