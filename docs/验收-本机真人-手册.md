## 0.5 选哪个 TTS（**先读这段，选错会得出错结论**）

本机两种 TTS 的实测差别是 3 倍（同一台 M5、同一个真 LLM）：

| 配置 | TTS 首片 | 口径B p50 | 说明 |
|---|---|---|---|
| 本地 `melo`（默认） | **2668ms（87%）** | **3067ms** | 整句阻塞合成，且耗时正比于字数（真 LLM 爱说 27 字长句→约 79ms/字） |
| 云 `dashscope` | **634ms（64%）** | **1009ms** | 流式，与 ECS 部署形态一致 |

⇒ **本机验收用云 TTS**：

```bash
export VOICE_PIPELINE_TTS_ENGINE=dashscope
```

理由：① 快 3 倍，真人对话能聊得下去；② 与线上（ECS 混合部署）形态一致，
本机验出的体验才对线上有参考价值；③ 本地 melo 另有两个已知短板——音量偏低
（RMS 峰值 0.031 vs kokoro 0.080）、单音色。

> ⚠️ **不要把 ECS 的 1553.9ms 当本机判据**（本手册初版犯过这个错）：那是
> **云 TTS** 的数，与本地 melo 不同口径。本机配云 TTS 实测 1009ms **快于** ECS
> 的 1553.9ms，差在 ASR——ECS 的 ASR RTF 0.044，本机 0.008。

## 1. 起服务（一条命令）

```bash
cd .

# ⚠️ 必须用 zsh：key 在 ~/.zshrc，非交互 bash 继承不到。
export VOICE_PIPELINE_TTS_ENGINE=dashscope        # 云 TTS，见 §0.5
export VOICE_EVENTS_JSONL="$HOME/.voice-pilot/turns.jsonl"   # 账单落盘

uv run uvicorn voice_pipeline.server.app:app --host 127.0.0.1 --port 8000
```

看到这条就说明 key 生效了（**没有** SimLlm 告警）：

```bash
curl -s http://127.0.0.1:8000/healthz     # {"status":"ok"}
```

> `VOICE_WS_TOKEN` 本机**不要设**——设了浏览器那栏就得填 token。

## 2. 开麦对话（Chrome，`http://localhost:8000`）

页面上的旋钮按这个来：

| 控件 | 选什么 | 为什么 |
|---|---|---|
| mode | `real-serial` | 已实测投机（pipelined）是净负债，真人验收不用它 |
| gating | `neural` | 默认档，判停 ~100ms |
| token | 留空 | 本机未启用鉴权 |

**说话方式**（决定这轮能不能验出东西）：

1. **正常语速说完整句**，比如「今天上海天气怎么样」——然后**停住别补话**，
   让 AI 接。这是验口径B 的基准轮。
2. **故意在句中停顿 300~500ms 再接着说**，比如「我想订……（停）……明天下午的会议室」。
   这是**抢话测试**：看 AI 会不会在你话没说完时抢答。这条比延迟数字重要。
3. **AI 正在播报时直接插话**，比如它说到一半你说「等一下」。这是**打断测试**：
   看它是否立刻停、并且**等你说完再答**（不是重开一轮、也不是一刀切静音）。

建议至少跑 **10 轮**：5 轮基准 + 3 轮句中停顿 + 2 轮插话打断。
样本不足 5 轮时分位数没有统计意义，脚本会自己标出来。

> 起服务后如需先自测链路（不用你开口），可以跑两个探针：
> `uv run python scripts/probe_multi_turn.py`（多轮）与
> `uv run python scripts/probe_bargein.py`（打断闭环，需服务在 8767 端口）。
> 2026-09-27 已跑过一轮，结果见 `docs/验收-本机真链路-20260927.md`。

## 4. 验收判据（先定好，免得事后找补）

| 判据 | 及格线 | 依据 |
|---|---|---|
| 口径B p50 | 本机配云 TTS：≤1500ms（实测 1009ms）；本地 melo 会到 3000ms 量级，属已知 | `docs/ecs-baseline.md` + 本手册 §0.5 |
| 抢话率（句中停 300~500ms） | **关键项**：AI 不得在停顿处抢答 | 与「不抢话」目标一致 |
| 打断响应 | 插话后 AI **立刻停**，且**等你说完再答** | 技术方案 §14 |
| 多轮连贯 | 第 2 轮能承接第 1 轮（如「那明天呢」） | `tests/test_multi_turn.py` |
| 有没有硬故障 | 无静音死锁、无错读、无循环自答 | — |

> ⚠️ **预期会暴露两个已知问题**，看到它们不算验收失败，算**如实记录**：
> ① **默认档 `neural` 可能把一句话切成两轮**——受控实验已确证（合成语音内部静音
>    150~240ms 超过 100ms 确认窗）。真人症状 = 「AI 在你说到一半时接话」。
>    这是现场复现它、并决定默认档是否退回 `conservative` 的依据。
>    ❌ **不要**再把它当成「ASR 首字丢字」（那是误诊，已于 2026-09-27 推翻：
>    字没丢，是轮次被切错，见 `docs/验收-本机真链路-20260927.md` §4）。
> ② **回声**——浏览器端有 AEC 免耳机，但如果你外放且音量很大，仍可能自激误触发打断。
>    出现就记下来，这正是「软件 AEC 列二期」的现实依据。
>
> ⚠️ **抢话必须靠耳朵听，不看账单字段**：`premature_eou` 在当前实现下**恒为 0**
> （`run_turn` 采完指标就 `reset()`，把「判停后又出现人声」的证据擦掉了），
> 它看着像「没抢话」，实际不反映任何东西。见同一份记录的 §5。

## 5. 这轮不验什么（说清楚，免得含糊）

- **不验并发**：单用户，共享 ORT session 上推理串行（差距表明列）。
- **不验公网**：本机 `localhost` 是安全上下文；公网开麦要域名 + TLS，未做。
- **不验尾音量化**：`barge_in_latency_ms` 只记服务端检测时刻，不含客户端播放缓冲
  残留音频的实际停播耗时——那需要带播放队列的真机测量。
