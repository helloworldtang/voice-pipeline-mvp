## 0.5 选哪个 TTS（**先读这段，选错会得出错结论**）

本机两种 TTS 的实测差别是 3 倍（同一台 M5、同一个真 LLM）：

| 配置 | TTS 首片 | 口径B p50 | 说明 |
|---|---|---|---|
| 本地 `melo`（默认） | **2668ms（87%）** | **3067ms** | 整句阻塞合成，且耗时正比于字数（真 LLM 爱说 27 字长句→约 79ms/字） |
| 云 `dashscope`（neural 档，2026-10-04 前） | **634ms（64%）** | **1009ms** | 判停 100ms；neural 已因真人抢话 3/3 退位 |
| **云 `dashscope` + conservative（当前默认）** | — | **913ms**（2026-10-05 实测 n=4，min 839 max 1262） | 判停 512ms；**口径B 不含判停等待，体感 ≈ 判停 + 口径B ≈ 1.4s** |

⇒ **本机验收用云 TTS**：

```bash
export VOICE_PIPELINE_TTS_ENGINE=dashscope
```

理由：① 快 3 倍，真人对话能聊得下去；② 与线上（ECS 混合部署）形态一致，
本机验出的体验才对线上有参考价值；③ 本地 melo 另有两个已知短板——音量偏低
（RMS 峰值 0.031 vs kokoro 0.080）、单音色。

> ⚠️ **不要把 ECS 的 1553.9ms 当本机判据**（本手册初版犯过这个错）：那是
> **云 TTS** 的数，与本地 melo 不同口径。本机配云 TTS 实测 1009ms **快于** ECS
> 的 1553.9ms，差在 ASR——ECS 的 ASR RTF 0.044，本机 0.008。


### 1.5 账单文件必须先隔离（否则记录被污染）

`~/.voice-pilot/turns.jsonl` 是**累积**文件（截至 2026-10-10 已有 125 行、3 个会话，
其中 122 行是 2026-10-08 `scripted_client` 跑的），而 `scripts/report_turns.py`
**不做会话过滤**——它把文件里的每一行都算作本轮。直接拿它出记录，得到的会是
「会话数：2+/轮次：125+」，本轮真人的数字被旧轮次稀释。

⇒ **每轮真人验收用一个新账单文件**（旧文件原样留着，不动它）：

```bash
VOICE_EVENTS_JSONL="$HOME/.voice-pilot/turns-$(date +%Y%m%d).jsonl" ./scripts/dev_server.sh
```

`dev_server.sh` 只在变量未设时才写默认路径，所以这样起服务 = 本轮从零开始记账。
下面 §3 出记录时读**同一个文件**。

> 就算你用的是累积的 `turns.jsonl` 也不至于出混合记录：§3 的命令带 `--since 今天`，
> 只统计本轮开始的会话（旧轮次留在文件里、不动它）。

## 2. 开麦对话（Chrome，`http://localhost:8000`）

页面上的旋钮按这个来：

| 控件 | 选什么 | 为什么 |
|---|---|---|
| mode | `real-serial` | 已实测投机（pipelined）是净负债，真人验收不用它 |
| gating | **`conservative`** | **第四次定档的默认档**（页面已默认选中），判停 ~512ms，句中停顿不抢话。**别选 `neural`**——真人实测抢话 3/3，已退位为实验档 |
| token | 留空 | 本机未启用鉴权 |

**照念剧本**（页面顶部「验收剧本」面板有同样的 10 句，念完自动亮下一句；
句子是实测选定的——kokoro 合成回灌真 ASR 打分，满分句优先，抢话句两段均可识别）：

| # | 类型 | 念什么 |
|---|---|---|
| 1 | 基准 | 今天上海天气怎么样 |
| 2 | 追问 | 那明天呢（验多轮承接） |
| 3 | 基准 | 明天要下雨吗 |
| 4 | 基准 | 给我讲个笑话 |
| 5 | 基准 | 你会说英语吗 |
| 6-8 | 抢话 | 我想订……（停半秒）……明天下午的会议室（另两句见页面） |
| 9-10 | 打断 | 随便问一句，AI 播报中直接说「等一下」/「停一下」 |

**说话方式**（决定这轮能不能验出东西）：

1. **正常语速说完整句**，比如「今天上海天气怎么样」——然后**停住别补话**，
   让 AI 接。这是验口径B 的基准轮。
2. **故意在句中停顿 300~500ms 再接着说**，比如「我想订……（停）……明天下午的会议室」。
   这是**抢话测试**：看 AI 会不会在你话没说完时抢答。这条比延迟数字重要。
3. **AI 正在播报时直接插话**，比如它说到一半你说「等一下」。这是**打断测试**：
   看它是否立刻停、并且**等你说完再答**（不是重开一轮、也不是一刀切静音）。

建议至少跑 **10 轮**：5 轮基准 + 3 轮句中停顿 + 2 轮插话打断。
样本不足 5 轮时分位数没有统计意义，脚本会自己标出来。

> 起服务后如需先自测链路（不用你开口），可以跑两个探针：
> `uv run python scripts/probe_multi_turn.py`（多轮）与
> `uv run python scripts/probe_bargein.py`（打断闭环，需服务在 8767 端口）。
> 2026-09-27 已跑过一轮，结果见 `docs/验收-本机真链路-20260927.md`。

## 3. 出验收记录（一条命令）

```bash
# 先看文件里有哪几段会话（--list 只列表，不出记录）
uv run python scripts/report_turns.py "$HOME/.voice-pilot/turns.jsonl" --list

# 出记录：只统计「今天开始的会话」——重连过、连了两段都会一起算进来
uv run python scripts/report_turns.py "$HOME/.voice-pilot/turns.jsonl" \
    --since "$(date +%Y-%m-%d)" \
    --out "docs/验收-本机真人-$(date +%Y-%m-%d).md"
```

> 只想出**最新一段**会话用 `--session last`；知道 id 就直接传 id。
> ⚠️ 不给任何过滤条件时，若文件里有多段会话，**记录里会写明「这是合并统计」并在 stderr 告警**——
> 不然后得到的就是「会话数 5 / 轮次 150」那种混合记录（2026-10-10 真实踩过一次）。

产出物包含：口径B 分布（n/min/p50/max）、**分格拆账**（判停 / LLM首token / 首句成 /
TTS首片各占多少）、**判停质量**（抢话率 / 漏判 / 打断次数）、逐轮明细（含用户与
AI 原话）。数字全部来自落盘账单，不经人工修饰。

## 5. 这轮不验什么（说清楚，免得含糊）

- **不验并发**：本轮是真人单路开口（一个人一次只能说一路），不压并发。
  注：并发能力**已于 2026-10-08 落地**（判据 9 转 ✅，会话独占推理槽 + 满载明确拒绝），
  已不是差距表项，只是本轮场景不涉及。
- **不验公网**：本机 `localhost` 是安全上下文；公网开麦要域名 + TLS，未做。
- **不验尾音量化**：`barge_in_latency_ms` 只记服务端检测时刻，不含客户端播放缓冲
  残留音频的实际停播耗时——那需要带播放队列的真机测量。
