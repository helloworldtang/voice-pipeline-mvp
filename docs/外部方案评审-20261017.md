# 外部方案评审（2026-10-17）

> 对象：一份针对本仓架构的优化建议（"句子级 → Token 级流水线"那套）。
> 逐条对照我们的**已实现**与**已实测**，只保留真正能落的部分。

## 一、逐条对账

| 方案建议 | 它的预期 | 我们的现状 / 实测 | 判决 |
|---|---|---|---|
| TTS 长连接预热 | −43ms | **已做，且更彻底**：预热 + 任务级预热，冷启动首轮 `tts.connect` **840→37ms**、口径B 1743→938 | ✅ 已超越 |
| EOU 动态静音窗 | −150~250ms | **测过并否证**：semantic 250ms 在句中停顿抢话 20~40%、neural 100ms 真人抢话 3/3；且 **EOU 不在口径B 内**（它进的是体感） | ❌ 不可取 |
| 文本分片触发 TTS（≥8 字） | −80~120ms | **已实现**（首句护栏，逗号处切）；实测 **−31ms** | ⚠️ 收益约为预期的 1/3 |
| Token 级 LLM-TTS 流水（不等整句） | −120~200ms | **本轮实测：−49ms**（见 §二） | ⚠️ 收益约为预期的 1/4 |
| ASR partial 预推理 | −100ms+ | **测过并否证**（M4 pipelined）：命中率 4%，p50 反而慢 651ms | ❌ 不可取 |
| Barge-in 打断 | 不直接降延迟 | **已实现**：三层 + 状态机 + 有界队列 + 客户端停播取证（1830/287ms） | ✅ 已有 |
| 端侧 TTS | −200~300ms | **本轮否证**：sherpa melo 7 字 1248ms（CoreML 1316）、kokoro/MPS 294ms（且语速异常） | ❌ 不可取 |
| 分层埋点 / P50·P90·P99 | 观测 | **已有** trace_id + span + 每轮瀑布；报告报 n/min/**p50**/max，**缺 p90/p99** | ⚠️ 可补 |

## 二、唯一真新的一条：增量文本喂 TTS（`streaming_call`）

方案说的"Token 级"在 DashScope 上**不用等新厂商**：`SpeechSynthesizer.streaming_call(text)`
可以多次追加、`streaming_complete()` 收尾。探针 `scripts/probe_tts_streaming.py`（冷态、同句、n=4）：

| 臂 | 首包 p50 | 说明 |
|---|---|---|
| A 整句 `call()` | **644ms** | 现在的行为（等句末标点） |
| B 增量 `streaming_call`（7 字 → 120ms → 9 字） | **595ms** | 首段文字到达就开始合成 |

**只省 49ms。** 原因与我们此前的实测一致：**TTS 首包是服务端固定成本，与文本长短基本无关**
（§一#6：首片对首句字数不敏感）。增量文本省下的只是"攒够句子"的那段时间——而这句话
按 4~8ms/字算也就 60~120ms。

⇒ 方案里 "−120~200ms" 的估计，**把 TTS 首包当成了随文本缩短而缩小的量**，这是它最大的算术偏差。
增量文本真正值钱的地方不在首音，而在**后段**：整段音频可以边生成边合成，消掉句间空档、缩短整轮墙钟。

## 三、两处口径要纠正

1. **"首音 856ms" 不含 EOU**：856 是口径B（说完→首音），EOU 的 500ms 在它**之前**，
   所以"EOU 是首音里最大单项"这个说法在本仓口径下不成立（体感才有它）。
2. **"端侧 TTS 消掉 200~300ms 网络"**：本机到 DashScope 的 TCP 只有 40ms，302ms 里绝大部分是
   **服务端合成**，不是网络。端侧换来的本地引擎是 294~1248ms，净亏。

## 四、值得采纳的两点（与延迟无关或很小）

- **p90/p99**：报告现在只到 max；加 p90/p99 能看见长尾（我们已知的尾部是冷启动与网络抖动）。
- **"断句差评率"**：主观项，无法自动量；但可以先用「首句护栏开关 + 真人听感」做一次小样本对照。

## 五、结论

方案的方向（串行 → 流式并行）与本仓一致，且**大部分已被我们实现或实测否证**；
其单项收益普遍**高估 2~4 倍**，根因是同一条：**TTS 首包是固定成本，不随文本变短而变小**。

当前地板仍是 **619ms**（本地 LLM + ASR 1 线程 + 云 TTS），其中 TTS 首片 344~421ms 是唯一门槛。
要跨 300，只能换一个**首包 ≤150ms** 的 TTS——这正是等讯飞 key 要量的事。
