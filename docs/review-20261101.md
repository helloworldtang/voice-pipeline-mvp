违背「缺了要响亮失败」的仓纪律。已修（见 §三 C1）。

### 2.2 延迟/CPU 微优化候选（未动手，按惯例先探针后 A/B）

1. **每帧最多 5 次纯 Python `rms_of`**：`barge_in.py:33`、`energy_gate.py:56`、
   `eou.py:131/204/387` 各自把 1600 样本跑一遍解释器循环，全在事件循环上。
   每帧算一次下传或 np 向量化，预估省 ~0.5–2ms/帧。**未量化，先探针**。
2. **real+pipelined 每帧两次 `text()` 抢 stream 锁**：session 为 EOU 打点一次
   （session.py:303），投机判断再一次（pipelined.py:135）。复用一次结果即可，
   收益需 A/B（锁只在与 decode 线程竞争时才有代价）。
3. 次要：pump 每音频帧 pydantic dump JSON（可模板化）；barge-in 检测晚于 ASR
   push 一跳（session.on_audio 内顺序调整）。两处均未见文档记载。

### 2.3 顺带的实验发现（无行动项，记录防复踩）

- **soxr `ResampleStream` 的滤波器 warmup 会吃掉整个首块**：160 样本（10ms）喂入
  `resample_chunk(..., last=False)` 输出 `size=0`，100ms（1600 样本）才出片。
  对真实句子无影响（讯飞首包远大于此），但给 provider 写单测的假数据必须 ≥100ms，
  否则剧本失真（本次写 xfyun 重试测试时踩到）。
- `error(turn_failed)` 由守卫**直发**（不进下行队列），可能抢在队列里的
  turn.start/asr.final 之前到达——错误帧是终态，乱序可接受；测试断言因此不依赖顺序。
